# Faculty Finder

A research mentor shortlist for students exploring faculty at Indian IITs and NITs. Search by institute, department or research interest, review profiles as they arrive, and export a shortlist as a PDF.

[Open the demo](https://kjhwgfd.vercel.app/) · [Development history](https://github.com/chitrakantverma/faculty-finder/commits/main/)

## Why I built it

Finding potential research mentors usually means moving between institute directories and individual faculty pages. This prototype brings an initial shortlist into one view so the next step is reviewing a person's research and official profile.

The first prototype was committed on **29 October 2025**. The **25 October 2026** maintenance pass keeps that history and improves the app's setup, stream handling and presentation.

## Try it

**Deployment status — 25 October 2026:** the sample shortlist and PDF download were checked in the deployed app. Live search currently returns “API key is not configured on the server.” Configure the server-side `API_KEY` in Vercel and redeploy to enable it.

Use **Load sample shortlist** to explore the result layout and PDF export without an API key. The sample profile is explicitly fictional. For a live search, choose an institute and add a department or research keyword.

**Search suggestions are generated by Gemini and are not verified faculty records.** Check names, research interests, contact details and opportunities against official institute pages before acting on them. This version does not browse or verify sources.

## What it does

- Filters a search by institute, department and research keyword.
- Displays complete profile records as the server streams them.
- Shows research interests, summaries and available contact/profile links.
- Exports the current shortlist as a PDF, including on mobile.
- Preserves received profiles if a later part of the response fails.
- Rejects malformed profile records, filters unsafe link protocols and removes duplicate name/institute pairs. These are format checks, not factual verification.

## Architecture

| Part | Responsibility |
| --- | --- |
| React + TypeScript | Search form, loading/error states and profile cards |
| `src/services/geminiService.ts` | Fetch, incremental decoding, record validation and deduplication |
| `api/search.ts` | Vercel Edge handler; calls Gemini with a server-side key |
| Gemini via `@google/genai` | Produces suggested faculty profiles from the supplied criteria |
| jsPDF | Generates the shortlist PDF in the browser |
| Vite | Frontend development and production build |

The browser posts search criteria to `/api/search`. The handler streams model output as newline-delimited JSON. The client buffers incomplete chunks and renders only complete records. The API key stays in the server environment.

### A technical decision: render complete records

Network chunks can end in the middle of JSON or a multi-byte character. Rendering each raw chunk would produce broken cards. The client uses a streaming `TextDecoder`, keeps the unfinished line, and validates each complete record before displaying it. An explicit error appears when malformed records are encountered; already received profiles stay visible.

## Run locally

Use Node.js 22 and npm.

```sh
git clone https://github.com/chitrakantverma/faculty-finder.git
cd faculty-finder
npm install
npm run dev
```

This starts the **frontend only**. The sample shortlist works here; live search needs the Vercel API route as well.

For the full app, use the official Vercel CLI, link the project when prompted, and add `API_KEY` to a local `.env.local` file using `.env.example` as the template:

```sh
npm install --global vercel
vercel dev
```

For deployment, configure the Vercel project's server environment variable **`API_KEY`**. The handler reads this exact name. Do not use `VITE_API_KEY` or place a key in frontend source. The current handler uses `gemini-2.5-flash`; provider access, availability and usage costs depend on the configured account.

## Checks

```sh
npm run typecheck
npm test
npm run build
```

The maintenance pass passed frontend type checking, a production build and six stream regression tests: arbitrary byte boundaries, missing final newline, duplicates/unsafe URLs, malformed records, interrupted responses, HTTP failures, blank criteria and oversized records. Some cases are combined in one test.

A live search request confirmed that the deployed backend currently has no `API_KEY` configured. Successful Gemini generation and factual result accuracy have not been validated in this pass. The regression tests use mocked responses.

## Repository layout

`src/` is the active frontend; `index.html` loads only `src/index.tsx`. `api/` contains the server route. The original root-level React files remain as legacy prototype code and are not mounted by the app. Changes should target `src/`.
